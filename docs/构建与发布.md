# 构建与发布

面向维护者的构建、测试与发布说明。日常使用请看[使用教程](使用教程.md)。

## 日常构建

```bash
npm install          # 依赖
node esbuild.mjs     # 构建（dist/main、dist/preload、dist/renderer）
npm run typecheck    # TypeScript 类型检查
npm run dev          # 构建并启动
npm run smoke        # 冒烟自检（主进程输出 [smoke] ok）
```

## 自动化验证（verify-* 脚本）

所有 `scripts/verify-*.mjs` 通过 Playwright 连接正在运行的应用做端到端验证：

```bash
npx electron . --remote-debugging-port=9222   # 带调试端口启动
node scripts/verify-selection-highlight.mjs   # 另开终端运行任一脚本
node scripts/verify-edit-context-menu.mjs
node scripts/verify-preview-image-click.mjs
node scripts/verify-preview-jump.mjs
```

- 测试钩子在 `src/renderer/main.ts` 的 `window.__typx`（setMarkdown / openProject / editorState / hookPreviewImage 等），改功能时同步维护对应 verify 脚本。
- **坑**：`typx://` 协议下 `page.reload()` 偶尔会拿到缓存的旧 `app.js`。重载后行为没变化时，先杀掉进程重启应用再判断。

## 为什么安装包在 GitHub Actions 上构建

`npm run dist`（electron-builder NSIS）在**非管理员**的 Windows 终端会失败：

1. electron-builder 下载 `winCodeSign-2.6.0.7z` 后由 7za 解压，其中 darwin 目录的
   `libcrypto.dylib`、`libssl.dylib` 是符号链接，非管理员无 `SeCreateSymbolicLinkPrivilege` →
   `Cannot create symbolic link: 客户端没有所需的特权` → 构建中止。
2. 已验证走不通的绕过：预填缓存（winCodeSign 缓存目录名**每次运行都变**，`%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\<随机数字>`）、手动补齐解压产物、Windows 11 自带 sudo（默认禁用）、开发者模式（未开启）。
3. 本机能成功的历史缓存（2026-08 之前）说明当年是在管理员终端构建的。

结论：安装包统一走云端（管理员权限的 windows runner，符号链接正常），本地不再折腾。
便携版 `npm run dist:dir`（`scripts/pack-portable.mjs`）不依赖 electron-builder，
本机随时可跑；它只产出目录不压缩 zip，发布用的 zip 由 CI 里的 `Compress-Archive` 生成。

## 发布流程（v0.6.4 起）

```bash
# 1. 版本号与提交
npm version 0.6.x --no-git-tag-version   # 同步 package.json + lock
git add -A && git commit -m "v0.6.x：……"
git push origin main

# 2. 打 tag 并推送 —— 自动触发 Actions 构建
git tag v0.6.x && git push origin v0.6.x
```

`.github/workflows/release-build.yml` 会在 windows-latest 上：`npm ci` → esbuild →
`electron-builder --win --publish never` → `dist:dir` → `verify:update` → 压缩便携版 zip →
生成 `SHA256SUMS.txt` → 以**草稿**形式上传 5 个资产到对应 tag。

补发已有 tag（workflow 必须已存在于 main）：手动 dispatch，`ref=main`，
`inputs.tag_name=v0.6.x`。

**草稿发布前核对**：下载草稿里的 `latest.yml` 确认 `version`、`path`、`sha512` 与安装包一致
（`electron-updater` 靠它给老用户推自动更新），然后编辑 Release 正文、把 draft 改为正式发布。

## 坑速查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 本地 `npm run dist` 下载 winCodeSign 超时 | app-builder 直连 GitHub CDN，不走 git 的代理 | 用 Actions；或临时 `HTTPS_PROXY=http://127.0.0.1:7897 npm run dist`（需 Clash 在运行） |
| `Cannot create symbolic link` | 非管理员解压 winCodeSign | 用 Actions；或本机开管理员终端跑一次 |
| CI 里 electron-builder 报缺 `GH_TOKEN` | CI 环境检测到 publish 配置会尝试自动上传 | workflow 已加 `--publish never`，上传交给 gh-release 步骤 |
| `git fetch/push` 连不上 `127.0.0.1:7897` | `~/.gitconfig` 给 github.com 配了本地代理，代理程序没在运行 | 先启动 Clash 等代理客户端 |
| 改了渲染层代码重载没生效 | `typx://` 协议缓存旧 `app.js` | 重启应用 |
