# TypX 使用教程

TypX 是一个本地优先的 Markdown 排版工具：打开你电脑上的文件夹写文章，套用主题排版，一键复制到微信公众号 / 知乎。默认完全在本机工作；只有你主动为某个项目连接坚果云时，该项目文件才会通过坚果云 WebDAV 同步。

## 一、安装与启动

### 方式 A：从源码运行（开发者）

```bash
git clone <仓库地址>
cd TypX
npm install
npm run dev        # 构建并启动应用
```

> 国内网络若 Electron 下载失败，改用镜像：
> `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`

### 方式 B：Windows 安装包（推荐）

下载发布页的 `TypX-Setup-x.x.x.exe`，双击进入安装向导；安装过程中可以查看并修改安装目录。安装完成后可从桌面或开始菜单启动 TypX，也可以在 Windows「设置 → 应用」中卸载。

从 **0.6.2** 起，安装版会在启动后静默检查 GitHub Releases。发现新版后自动在后台下载，侧边栏「设置」会显示进度；下载完成后可点「重启并安装」，也可以在正常退出 TypX 时完成覆盖更新。升级到 0.6.2 的这一次仍需手动下载安装包，之后的版本才可直接在 TypX 内更新。

### 方式 C：免安装便携版

下载发布页的 `TypX-x.x.x-win-x64-portable.zip`，解压到任意目录，双击 `TypX.exe` 即可运行。不写注册表，删除文件夹即可卸载。

> 便携版不自动覆盖自身；请从发布页下载新版并解压替换。需要应用内自动更新时，请使用 Windows 安装版。

## 二、界面总览

![TypX 主界面：项目文件树、Markdown 编辑器和实时排版预览](images/ui.png)

> 主界面保持「项目 → 写作 → 发布」从左到右的固定顺序。第一次使用时，先点左下角「打开文件夹」，再从文件树选择一篇 Markdown 文章。

- **① 左侧项目区**：当前项目、文章目录树、打开文件夹和全局设置；点项目名展开项目切换与坚果云操作
- **② 顶部文档区**：显示当前文件和保存状态；右侧的「编辑 / 分屏 / 预览」切换全局视图
- **③ 中间编辑区**：CodeMirror 编辑器，支持 Markdown 语法高亮、自动换行和「复制 Markdown」
- **④ 右侧发布区**：主题、发布设置、同步滚动和平台复制都集中在预览标题栏
- **⑤ 底部状态栏**：显示光标行列、字数、编码和文件类型

### 全局设置与软件更新

左下角「设置」现在只放应用级入口：软件更新，以及发布与主题设置。点「检查更新」可立即查询；后台下载不会打断写作，下载完后按钮会变为「重启并安装」。如果当前文章有未保存修改，TypX 会先保存，保存失败时不会强行重启。

![全局设置：查看当前版本、检查更新，并进入发布与主题设置](images/guide-app-settings.png)

## 三、项目系统

TypX 用「项目」管理你的文章文件夹，类似 IDE 的工作区：

- **自动登记**：任何一次「打开文件夹」都会把该目录登记为项目
- **自动恢复**：启动时自动打开最近使用的项目，并恢复该项目里**上次编辑到的那篇文章**
- **多项目切换**：点侧边栏顶部「📁 项目名 ▾」弹出项目面板：
  - 点击项目条目即切换（有未保存修改会先确认）
  - 悬停条目出现 ✕，可从列表移除（只删记录，不动磁盘文件）
  - 面板底部「＋ 打开新文件夹…」添加新项目
- 文件树自动递归扫描 `.md` / `.markdown` / `.mdx`，跳过 `node_modules`、`.git` 等目录；文件夹在外部有增删改时自动刷新，正在编辑的文件被外部修改且本地无改动时自动重载

![点击侧栏项目名后，可连接坚果云或进入项目切换](images/guide-project-menu.png)

> 项目菜单只放项目级操作：同步、切换项目和打开新文件夹；文章操作仍留在文件树右键菜单中。

### 坚果云同步（可选）

1. 点左侧项目名，再点「连接坚果云」
2. 填写坚果云账号邮箱、**第三方应用密码**和云端目录（默认 `/TypX/项目名`）
3. 选择是否开启「保存文章后自动同步」，点「连接并同步」
4. 连接后仍在项目菜单中执行立即同步、修改设置、打开坚果云或断开连接

![坚果云同步设置：填写账号邮箱、第三方应用密码和云端目录](images/guide-nutstore-sync.png)

> 此处必须填写坚果云「第三方应用管理」生成的应用密码，不是网页登录密码。截图中的字段均为演示值。

同步采用本地优先的安全合并：只存在一端的文件会补到另一端；两端同时修改同一文件时，当前本地版本继续作为主文件，云端版本另存为 `文件名.坚果云冲突-时间戳.md`，避免静默覆盖。当前版本不会传播删除操作，误删一端后可由另一端恢复。单文件上限 100 MB，构建目录、隐藏目录和 `.git`、`node_modules` 等不会同步。

应用密码不会写入 `preferences.json`，而是使用操作系统安全存储加密保存。坚果云需要使用“第三方应用管理”生成的应用密码，不能直接填写网页登录密码。

## 四、写文章

- **打开文章**：左侧文件树点击任意 `.md` 文件
- **保存**：`Ctrl+S` 写回原文件；状态栏实时显示「● 未保存 / 已保存」和字数
- **外部修改**：文章被其他编辑器改动时（如 Obsidian、VS Code），TypX 自动重载；如果你本地有未保存修改，只提示不覆盖
- **编辑器字号**：「设置」→「发布与主题设置」→ 编辑器字号（12–24px）
- **已发布标记**：文件树中右键文章 → 「✅ 标记为已发布公众号」，文件名后会出现绿色「已发布」徽章，侧栏显示统计，再次右键可取消。标记按项目保存在本地，用来记录哪些文章已经发过，避免重复上传

![右键文章可标记发布、用默认程序打开或在资源管理器中定位](images/guide-file-menu.png)

> 右键菜单只影响当前文章；「标记为已发布公众号」是本地记录，不会自动登录或操作公众号后台。

## 六、主题系统

### 内置主题（7 套）

| 主题 | 风格 | 适合 |
|---|---|---|
| 简约白 | 黑白极简，GitHub 风 | 通用 |
| 橙心 | 橙色标题 + 暖色块 | 通用、随笔 |
| 蓝绿清新 | 青绿色系 | 通用、技术 |
| 优雅紫 | 紫色标题条 + 淡紫块 | 生活、文艺 |
| 极客黑 | 深色底代码风 | 程序员读者 |
| **墨青标签** | 深黑灰 H2 标签块 + 珊瑚红加粗 + 墨青蓝斜体 | 技术长文（取自 Typlatex 装修） |
| **墨笺论文** | 衬线宋体 + 首行缩进 + 两端对齐 + 三线表 + 深色标签 H2，完整学术排版 | 论文风长文（Typlatex 完整移植） |

### 自定义主题

1. 点预览标题栏的调节图标，或左下角「设置」，打开「发布与主题设置」
2. CSS 编辑框里会预填当前主题的样式，直接修改（可先点「仅预览」看效果，不满意不保存）
3. 满意后点「保存并应用」——主题名可自定义，保存后出现在主题下拉的「我的主题」分组
4. 「删除此主题」可删除自定义主题（内置主题不可删）

![发布与主题设置：主题名称、复制方案、文末推荐和 CSS 集中配置](images/guide-settings.png)

> 「公众号 / 知乎」两套复制方案彼此独立。切换平台后再修改公式或文末推荐，只会影响当前平台。

CSS 按普通网页写法即可（选择器直接用 `h1`、`p`、`code` 等标签名），复制时 TypX 会把计算样式自动内联到每个元素上，粘贴到公众号 / 知乎不依赖外链样式。

### 其他排版设置（同一窗口）

- **文末脚注**：复制时自动附加在文末的居中灰字（如「本文使用 TypX 排版」），留空则不加
- **复制方案**：按平台分别配置（见[第九节](#九复制到公众号完整流程)）

## 七、数学公式

### 写法

```markdown
行内公式：质能方程 $E = mc^2$，欧拉公式 $e^{i\pi} + 1 = 0$。

块级公式（$$ 独占一行）：

$$
\int_{-\infty}^{\infty} e^{-x^2} \, dx = \sqrt{\pi}
$$
```

- 预览由 KaTeX 渲染，支持绝大多数 LaTeX 语法（上下标、分数、根号、矩阵、求和……）
- `$` 紧贴文字或标点也能识别（如 `($x$)`）；**正文中的美元符号写 `\$` 转义**，例如 `\$100`
- 单行块级写法 `$$ xxx $$` 也支持

### 复制时的公式处理（按平台独立配置）

| 模式 | 原理 | 适用 |
|---|---|---|
| 转行内 SVG（公众号默认） | MathJax 生成无 `defs` 的矢量 SVG，随字号缩放、无需图床、几百个公式也稳定 | **公众号（已实测验证）** |
| 转截图 PNG | 逐个截屏上传图床换外链 | 个别平台不支持 SVG 时 |
| 原样 HTML（知乎默认） | 公式 HTML 逐元素内联样式 | 知乎等对 HTML 宽容的平台 |

## 八、图片与图注

### 图片

```markdown
![说明](images/pic.png)          ← 相对路径（推荐，跟随项目）
![说明](./images/pic.png)        ← 同上
![说明](D:\docs\images\pic.png)  ← Windows 绝对路径
![说明](https://example.com/a.png) ← 网络外链
```

- 预览中本地相对路径图片通过本地协议直接显示，中文文件名、带空格都支持
- **复制时**：本地图片会被读取并以 base64 编码进剪贴板，公众号 / 知乎编辑器粘贴时一般会自动转存到平台图床；图片很多或平台转存失败时配置[图床](#十一图床配置详解)
- 网络外链图片原样保留，由平台转存

### 图注（墨青标签 / 墨笺论文主题）

图片单独成段，空一行后写**整段斜体**，自动变成蓝色居中的图注：

```markdown
![实验装置](images/setup.png)

*图 1：实验装置示意图*
```

## 九、复制到公众号（完整流程）

1. 写好文章，右侧确认排版效果
2. 点右上角主按钮「**复制到公众号**」——提示会显示实际处理（如「382 个公式已转 SVG」）；按钮右侧下拉菜单可以切换复制目标
3. 打开公众号后台图文编辑器，`Ctrl+V` 粘贴
4. 检查：标题样式、公式（矢量图）、图片（应已被转存为 mmbiz.qpic.cn 链接）

![复制按钮下拉菜单：公众号、知乎、Markdown 和发布设置集中在一个入口](images/guide-copy-menu.png)

> 主按钮执行上次选择的平台；右侧箭头只负责切换目标。这样顶部不会重复出现多个平台按钮。

**公众号方案默认配置**（「发布与主题设置」→ 复制方案 → 公众号）：

- 公式：转行内 SVG（微信编辑器会剥掉公式 HTML 和 base64 图，但接受无 `defs` 的 SVG——这是 mdnice/doocs 验证过的方案）
- 图片：base64 直贴（图片不多时实测可用）；文章配图很多时建议开图床

**文末推荐（按平台独立配置）**：「发布与主题设置」→ 复制方案 → 文末推荐，填入 Markdown 格式的推荐链接。复制时会**自动加一条分割线**，渲染后追加到正文末尾（文末脚注之前）。典型用法：

```markdown
合集快速链接: [理解深度学习](https://mp.weixin.qq.com/mp/appmsgalbum?...album_id=xxx)  [CMOS工艺合集](https://mp.weixin.qq.com/mp/appmsgalbum?...album_id=yyy)

领域精读合集: [Thin Films Technologies Review](https://mp.weixin.qq.com/mp/appmsgalbum?...album_id=zzz)
```

公众号和知乎各配各的（比如知乎填知乎专栏/合集链接），留空则不追加。

**公众号的已知限制**：

- base64 图片可能被过滤（表现为贴过去图片空白）→ 开图床
- 公式 SVG 颜色跟随正文颜色（`currentColor`），极客黑深色主题下公式也是浅色，浅色主题同理
- 衬线字体（墨笺论文）在手机端回退为系统宋体，观感基本一致

## 十、复制到知乎

1. 点复制按钮右侧的下拉箭头，选择「**复制到知乎**」；以后主按钮会记住知乎作为默认目标
2. 打开知乎编辑器（专栏/回答均可），`Ctrl+V` 粘贴

知乎方案默认：公式原样 HTML（知乎对富文本 HTML 更宽容）、图片 base64（知乎会自动转存）。这条管线是独立配置的初始方案，可根据自己的实测在「复制方案 → 知乎」里随时调整，不影响公众号方案。

## 十一、图床配置详解

**什么时候需要图床**：公众号粘贴后图片空白/丢失、或文章配图数量很多时。图片不多时通常不需要（base64 直贴即可，知乎更是完全不需要）。

![图床设置：在 Gitee、SM.MS、GitHub 和关闭之间选择](images/guide-image-host.png)

> Token 输入框不会出现在教程截图中。正式使用时 Token 仅保存在本机，不要把配置文件或带 Token 的截图分享给他人。

### Gitee（国内快，推荐）

1. 注册/登录 [gitee.com](https://gitee.com)，新建一个**公开**仓库（例如 `images`，专门放图）
2. 头像 → 设置 → 安全设置 → **私人令牌** → 生成新令牌，勾选 `projects` 权限，复制令牌
3. TypX「发布与主题设置」→「图床设置」→ 选 **Gitee**：
   - 令牌：粘贴私人令牌
   - 仓库：`你的用户名/images`
   - 分支：默认 `master`（按仓库实际填）
   - 目录：仓库内存放目录，如 `typx`
4. 点「测试图床（上传 1×1 测试图）」→ 显示 ✅ 和图片链接即成功 → 保存

> Gitee 上传接口有频率限制（约每小时 20 次），一次复制大量图片可能部分回退 base64。

### GitHub（无频率限制，国内网络可能不稳）

1. 新建公开仓库 + 生成 Personal Access Token（需 `repo` 权限）
2. 「发布与主题设置」→「图床设置」→ GitHub：填 Token、`用户名/仓库`、分支（常为 `main`）
3. 链接风格默认 jsDelivr CDN；粘贴后图片不显示时可切换 fastly 或 raw 试试

### SM.MS（最简单，免建仓库）

1. 注册 [sm.ms](https://sm.ms)（免费 5GB），访问 [sm.ms/apitoken](https://sm.ms/apitoken) 生成 API Token
2. 「发布与主题设置」→「图床设置」→ SM.MS → 只需填这一个 Token

### 图床工作原理

- 复制时，本地图片（和公式截图）自动上传图床，换成 `https` 外链——公众号粘贴时只转存外链图
- 图片按**内容哈希命名**：同一张图只占用一个路径；本地还有上传缓存（`upload-cache.json`），同一张图重复复制秒回、不再消耗请求次数
- 关闭图床时一切回到 base64 方案，随时切换

## 十三、数据存储与备份

默认数据都在本地；只有主动连接坚果云的项目会同步到你自己的坚果云账号：

| 文件 | 内容 | 位置 |
|---|---|---|
| `preferences.json` | 项目列表、主题、图床配置、复制方案等全部偏好 | `%APPDATA%\TypX\` |
| `upload-cache.json` | 图床上传缓存（内容哈希 → 外链） | `%APPDATA%\TypX\` |
| `sync-credentials.json` | 经操作系统安全存储加密后的坚果云应用密码 | `%APPDATA%\TypX\` |
| `sync-state/` | 各项目的文件哈希与 WebDAV ETag，用于安全合并 | `%APPDATA%\TypX\` |

换电脑迁移：文章可重新从坚果云同步，也可以手动拷贝项目目录和偏好文件。坚果云密码绑定当前操作系统的加密存储，换电脑后需要重新连接。图床 Token 仍以明文保存在本机 `preferences.json`，请勿把该文件分享给他人。

## 十四、常见问题 FAQ

**Q：公式复制到公众号乱码/散架？**
确认「复制方案 → 公众号 → 公式复制」选的是「转行内 SVG」。这是微信唯一稳定的公式方案（微信不支持公式 HTML，也不收 base64 图）。

**Q：公式预览正常，但复制提示「N 个公式按 HTML 原样复制」？**
说明该平台方案选了「原样 HTML」。公众号请改回 SVG。

**Q：图片粘贴到公众号不显示？**
图片不多时先确认是否开了「复制时处理本地图片」；仍不行则配置图床（Gitee 最省事）。知乎无此问题。

**Q：窄图片粘贴后不居中/偏移？**
已修复（复制时恢复 `margin:auto` 自适应居中）。如仍出现，请在 GitHub 提 issue 附截图。

**Q：墨笺论文主题的宋体在手机上还在吗？**
公众号会回退为手机系统衬线字体（iOS 宋体 / 安卓思源宋体），衬线观感基本保留，但与电脑预览不完全逐像素一致。

**Q：编辑（无预览）模式下点复制，公式截图模式会失效吗？**
不会，应用会临时切回分屏截屏再还原。SVG 模式则完全不受视图模式影响。

**Q：能把生成的排版导出成 HTML 文件吗？**
当前版本聚焦复制粘贴工作流；可用「复制 Markdown」+ 任何静态渲染器补充。

**Q：支持哪些 Markdown 语法？**
GFM 全套：表格、任务列表、删除线、引用块、代码块（highlight.js 高亮）等。

**Q：为什么 0.6.1 不能直接在软件里升级？**
自动更新程序从 0.6.2 才被安装进 TypX，所以需要手动安装一次 0.6.2。以后使用安装版时，TypX 可自动检查、下载并覆盖原安装目录；也可随时从左下角「设置 → 检查更新」手动触发。

**Q：检查更新提示“仅安装版”怎么办？**
当前运行的是便携版或源码开发模式。便携版请手动下载新版 ZIP；正式安装版才会启用应用内更新。
